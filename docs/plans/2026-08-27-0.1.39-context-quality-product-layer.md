# Desktop 0.1.39 Context Quality Product Layer

**Goal:** Turn the existing deterministic long-context benchmark into an explicit, user-visible quality workflow for the currently configured DeepSeek Harness model route, without replacing or modifying the official compaction engine.

**Architecture:** Keep `@harness-design/dsh-context-bench` as the metric contract and CI authority. Add a bounded runtime adapter in `@harness-design/dsh-orchestrator`: it invokes the current session's official `ctx.llm` route after explicit user confirmation, stores sanitized bounded summaries under the project-local `.dsh-harness` directory, and exposes them through the existing loopback RPC and Agent Harness dashboard. Raw prompts, model output, credentials, user home paths, and hidden reasoning are never persisted.

**Product boundary:** The feature measures retention for versioned scenarios. It is not a claim that a model is universally intelligent, that compression is lossless, or that the implementation is globally state of the art.

## User flow

1. The Agent Harness panel gains a `上下文质量` tab.
2. The tab explains cost and data handling before any model call.
3. The user chooses `32K` or `128K` and clicks `开始检测`.
4. The app verifies that the current adapter reports enough context capacity. Unknown or insufficient capacity fails closed.
5. Three seeded probes run through the current session's official provider/model and credential seam.
6. Only sanitized metrics and token/duration totals are persisted.
7. The panel shows the latest result, failed dimensions, per-scale trend, and the exact model route used.

## Metrics

- Critical recall
- Exact literal recall
- Latest-state accuracy
- Stale leakage
- Constraint recall
- Pending-work recall
- Tool integrity
- Section completeness
- Input/output/cache-read tokens
- Duration and hard-failure count

The initial live gate requires three samples. Critical facts, stale-state leakage, and tool pairing are hard gates; the remaining semantic metrics are reported independently so users can see partial degradation without hiding it behind one aggregate score.

## Data model and privacy

- Store: `<workspace>/.dsh-harness/context-quality.json`
- Schema version: `1`
- Maximum retained runs: `120`
- Atomic write through a temporary sibling file and rename.
- Reject non-finite/out-of-range metrics, credential-shaped text, and absolute user-home paths.
- Persist model route, scale, metrics, usage, duration, timestamp, and pass/fail only.
- Do not persist prompt corpus, raw completion, API keys, provider headers, or error stacks.

- No changes to official DSH compaction, session replay, or token-meter behavior.

- No deep WorkBuddy/CodeBuddy/TRAE/Qoder migration.
