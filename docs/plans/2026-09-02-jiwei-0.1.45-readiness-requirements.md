# 积微 JIWEI 0.1.45 仓库精修与真实场景验收需求

## 1. 文档目的

本需求用于指导积微 `0.1.45` 的发布前工作。当前 `0.1.44` 已完成独立品牌首发、三平台构建和自动化测试，本阶段不以增加大功能为目标，而是完成以下闭环：

1. 让公开仓库的产品表达、开源归属和技术边界准确一致；
2. 清理活跃文档中的过时第三方宣传、安装指引和旧产品名称；
3. 对附件、MCP 连接器、TAPD、iWiki、微信公众号导入和“我的大脑”进行端到端验收；
4. 只修复验收中被证实的问题；
5. 满足门禁后发布 `0.1.45`。

## 2. 当前基线

- 基线分支：`main`
- 基线提交：`4cdd16f`（`fix: make Finder attachment parsing portable`）
- 当前公开版本：`desktop-v0.1.44`
- 内置官方运行时：`@deepseek-ai/dsh 0.1.1-rc.2`
- 当前桌面自动化测试：210 项通过
- 当前发布平台：Windows x64、macOS Intel、macOS Apple Silicon
- 当前已知发布限制：安装包尚未配置 Apple Developer ID 和 Windows 代码签名证书

## 3. 产品与开源边界

### 3.1 必须保留的内容

以下内容属于法律归属、兼容性或真实技术来源，不得为了“去除别人痕迹”而删除或伪造：

- `LICENSE`、`NOTICE.md` 和各组件目录中的许可证与版权声明；
- DeepSeek Harness 与 `@deepseek-ai/*` 的上游依赖名称；
- 实际仍在使用的 npm 包名、scope、Cordis 插件 id 和兼容层标识；
- `package.json` 中指向真实上游来源的 repository 字段；
- 历史 ADR、历史计划和 Git 历史中的真实来源记录；
- 为遵守 BSD、MIT 等许可证所需的归属说明。

### 3.2 应当清理的内容

以下内容属于当前产品公开表达，应统一到积微并删除过时宣传：

- 根 README、安装文档、发布说明中的旧产品名称和旧宣传口径；
- 活跃子包 README 中引导用户克隆第三方仓库、安装旧聚合包或进入旧目录的命令；
- 旧作者的宣传截图、社群文案、推广链接和与当前产品无关的推荐语；
- 将积微描述为 DeepSeek 官方产品或获得第三方官方背书的措辞；
- 将尚未真实验证的能力描述为“已完全支持”的措辞；
- 任何包含本地绝对路径、个人账号、令牌、Cookie 或内部地址的公开材料。

### 3.3 不做破坏性命名迁移

本阶段不批量重命名 `@linxin666/*`、`@harness-design/*` 等现有包，也不修改 Cordis 插件 id。此类迁移会影响 profile、聚合包、锁文件、已安装用户和升级兼容，应单独设计迁移方案。当前只处理用户可见品牌与过时文档。

## 4. 目标用户与核心场景

### 4.1 小白产品经理

- 能拖入或粘贴 JSON、TXT、Office 文档和图片；
- 能看到正常文件卡片，而不是内部附件 id 或工具指令；
- 能从 `mcp.json` 一步进入连接器预览，不需要理解 app.asar、Cordis 或配置目录；
- 能把工作对话、文章和手工内容沉淀进“我的大脑”。

### 4.2 想扩展能力的非专业用户

- 能看懂连接器的配置、凭证、运行环境和 Harness 注册状态；
- 能区分“已保存”“已授权”“握手成功”“工具可用”；
- 能在失败时看到可执行的修复建议，而不是让 Agent 无边界搜索本机文件。

### 4.3 开源贡献者

- 能从 README 和 CONTRIBUTING 快速理解项目边界；
- 能清楚区分积微原创产品层、DeepSeek Harness 上游和第三方组件；
- 能用可复现步骤和脱敏证据提交问题；
- 不会被过时的仓库路径、旧安装命令和旧品牌截图误导。

## 5. 功能需求

### FR-01 公开仓库表达一致

- 根 README 中英文版必须使用积微定位、当前截图和当前版本能力。
- “开源许可与第三方声明”必须区分项目原创代码许可和第三方组件许可。
- 不得暗示第三方对积微提供官方背书。
- CONTRIBUTING 必须明确禁止提交访问令牌、Cookie、密码和未脱敏配置。
- SECURITY 必须继续提供私密漏洞报告路径。

### FR-02 可重复的品牌与旧文案审计

- 新增自动审计脚本，扫描活跃公开文档、品牌素材索引和发布配置。
- 审计必须采用“禁止项 + 明确允许项”策略，避免误删许可证、历史文档和技术标识。
- CI 或本地 release gate 必须能执行该审计。
- 发现旧安装命令、旧产品名、私有路径或凭证形态时必须失败并指出文件。

### FR-03 原生附件端到端验收

- Finder 复制粘贴、拖拽和文件选择均应生成原生文件外观。
- JSON、JSONC、YAML、Markdown、TXT、CSV、XML、DOCX、XLSX、PPTX 应按当前策略读取。
- PNG、JPEG、WebP、GIF 保持官方图片路径。
- 对话发送后只显示可理解的文件名，不显示 `file_*`、内部 RPC 名或“调用某工具”的提示语。
- Agent 仅在需要时读取文件；敏感字段在跨越 renderer/Host 边界前脱敏。
- `.env`、密钥、旧 Office、PDF、压缩包和无法安全脱敏的内容继续 fail closed。

### FR-04 MCP JSON 导入与连接器归位

- 附件中的 TAPD 配置应关联到官方 TAPD 卡片，不额外生成重复通用卡片。
- 未识别的 MCP server 应按 server name 创建独立自定义连接器。
- 导入预览必须展示将更新、创建、跳过或冲突的项目。
- 令牌只进入桌面主进程加密存储，不出现在渲染器、日志、错误信息和截图中。
- 再次导入相同官方 provider 应更新原连接器而不是重复创建。
- 内置和自定义连接器都必须提供查看/修改配置入口。

### FR-05 MCP 健康状态真实可信

- “已接入”只表示配置已保存并注册，不等于工具可用。
- 远程 MCP 只有在 `initialize` 和 `tools/list` 均成功且至少返回一个工具时才显示“测试通过”。
- HTTP 302 登录跳转显示“待授权”或明确认证失败，不得视为握手成功。
- 401/403、超时、DNS、命令缺失、OAuth 待授权和工具列表为空必须分类展示。
- Agent 请求 TAPD/iWiki 内容时应优先调用已注册 MCP 工具，不得退回猜测网页 API、索要 Cookie 或扫描 app.asar。

### FR-06 TAPD 真实账号验收

- 使用应用内连接器配置入口保存测试凭证，禁止在聊天中粘贴令牌。
- 验证 TAPD 连接器经过 `initialize` 与 `tools/list` 后向 Harness 注册工具。
- 在新会话中通过 Agent 读取一条用户授权范围内的 TAPD 需求，并确认结果来自 MCP 工具调用。
- 断开或删除连接器后，相同请求必须明确报告工具不可用，不得使用历史结果冒充实时读取。

### FR-07 iWiki 真实账号验收

- 明确 iWiki 使用的认证模式；若需 OAuth，则提供可见授权入口和授权完成后的状态刷新。
- 未授权时不得显示“已可用”。
- 授权后必须通过 MCP `tools/list` 和一次只读内容请求验证。
- 取消授权、令牌过期和浏览器关闭必须得到可恢复状态，不得无限等待。

### FR-08 “我的大脑”知识闭环验收

- 待确认和已沉淀使用同一主内容区的视图切换或响应式列表，不再因某一列为空留下大面积死区。
- 待确认和已沉淀条目均可编辑标题、正文、分类和标签。
- 支持手工粘贴内容、公开 HTTPS 链接和会话候选导入。
- 用户确认前，模型整理结果不能自动进入已沉淀库。
- 模型加工必须调用客户端当前已配置模型，并显示模型名称、成功或失败状态。
- 每条知识保留来源、时间和可追溯信息；不得保存隐藏推理、完整凭证或未脱敏附件。

### FR-09 微信公众号文章导入

- 精确支持 `https://mp.weixin.qq.com/s/...` 文章链接。
- 静态解析成功时直接提取；遇到平台验证时进入隔离的微信浏览会话回退。
- 回退浏览器只允许微信内容域，不放宽通用 URL 导入的 SSRF 策略。
- 验证页、登录页和参数错误页不得保存为知识正文。
- 成功结果至少包含标题、作者或来源、正文、原链接和抓取时间。

### FR-10 发布与回滚

- 验收中发现的问题必须先写失败测试，再做最小修复。
- 只有自动化、隔离 GUI 验收和用户辅助真实账号验收达到门禁时才发布 `0.1.45`。
- 失败时保留 `0.1.44` 为稳定回滚版本。
- 不修改已发布标签，不覆盖既有 Release 资产。

## 6. 非功能需求

### NFR-01 安全

- Renderer 不接收明文连接器密钥、API Key、Cookie 或 Authorization header。
- 所有日志、截图、fixture 和测试报告必须通过敏感信息扫描。
- 真实账号验收使用应用凭证 UI 或本机环境，不把秘密写入仓库和对话。
- 外部 URL 继续执行 HTTPS、DNS、重定向、大小和内容类型限制。

### NFR-02 可恢复性

- 网络、OAuth、MCP 和模型请求均有明确超时和取消路径。
- 连接器测试不得写入半完成状态。
- 重新配置失败不得破坏上一份可用配置。
- 知识导入失败不得创建伪成功记录。

### NFR-03 跨平台

- Windows x64、macOS x64、macOS arm64 必须完成测试、打包和包内运行时校验。
- 路径解析测试必须显式覆盖 POSIX 与 Windows 规则，不能依赖 CI runner 当前平台。

### NFR-04 可观测性

- 测试报告记录版本、平台、步骤、结果、耗时和脱敏诊断。
- 用户可区分配置、凭证、运行环境、授权、Harness 注册和工具可用状态。

### NFR-05 文案真实性

- 只描述代码或验收证据支持的能力。
- 账号依赖、企业网络依赖和实验性能力必须明确标注。
- 不使用“全面支持”“一定可用”“官方认证”等未经证明的表述。

## 7. 验收矩阵

| 领域 | 自动化 | 隔离桌面验收 | 用户辅助真实验收 |
| --- | --- | --- | --- |
| 开源与品牌 | 必须 | README/截图检查 | 不需要 |
| 文件附件 | 必须 | Finder/拖拽/发送 | 用户抽查 |
| MCP JSON 导入 | 必须 | fixture 导入 | 用户自己的脱敏 JSON |
| TAPD | fake MCP 必须 | 导入与状态 UI | 必须 |
| iWiki | fake OAuth/MCP 必须 | 授权状态 UI | 条件允许时必须 |
| 微信文章 | 静态/挑战页 fixture 必须 | 隔离浏览器回退 | 必须 |
| 我的⼤脑 | store/UI/model mock 必须 | 完整知识闭环 | 用户抽查 |
| 三平台安装包 | 必须 | 当前 Mac 本地安装 | Windows 用户抽查可后补 |

## 8. Release Gate

`0.1.45` 发布前必须满足：

1. 品牌/旧文案审计通过；
2. `pnpm test`、`pnpm typecheck`、`pnpm build` 全部通过；
3. `pnpm aggregate:check`、`git diff --check` 通过；
4. 桌面包敏感信息扫描无阻塞项；
5. macOS arm64 本地 DMG 安装验收通过；
6. GitHub Actions 三平台构建与包校验通过；
7. TAPD 真实只读请求通过；
8. iWiki 若受企业授权或网络阻塞，必须记录为外部阻塞，产品不得显示假成功；
9. 微信文章真实链接导入成功，或明确复现并修复失败原因；
10. “我的大脑”创建、编辑、分类、确认、链接导入和模型整理闭环通过。

## 9. 非目标

- 本轮不做云端知识库同步、向量数据库、知识图谱和多人协作；
- 不做 npm scope 和 Cordis id 的破坏性重命名；
- 不修改 `node_modules/@deepseek-ai/*` 上游源码；
- 不绕过微信、TAPD 或 iWiki 的登录、安全验证和权限控制；
- 不新增 PDF、旧 Office、压缩包和任意二进制解析；
- 不购买或生成 Apple/Windows 签名证书；
- 不把真实企业凭证写进测试 fixture、日志或文档。
