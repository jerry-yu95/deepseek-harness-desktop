# 阅读工作流二轮修复

依据用户最新五张截图，保留未提交工作区与现有安装包；本轮实现与合成验证，不调用真实模型、不读取凭证、不自动提交或发布。

## 设计与边界

1. 摘要：复现 2000 token 截断。通过官方 SDK 的确切路由元数据选择可用的关闭推理档位，使用有界输出预算；不按模型名字猜能力，不把截断 JSON 当作成功。压缩目标摘要长度，并提供明确的重试说明。
2. 视频：提取时识别播放器 DOM，替换为固定视频占位，丢弃内部按钮文字。正文位置保留，不转录、不播放或下载视频；提供前往原文章的入口。普通正文中“关注、分享”等词不能被全文删除。
3. 编辑：沿用阅读型排版，用标题、段落和要点分块编辑。保留旧文本内容，只有用户编辑并保存时才写入。原始 Markdown 整段编辑虽实现简单，但不能解决截图里的阅读/编辑割裂；不引入富文本 HTML 执行面。
4. 入口：保留三个快捷按钮，分别定位原文、我的笔记、AI 摘要；打开摘要页不自动调用模型。只保留阅读按钮的方案更简洁，但会增加笔记和摘要的操作步骤。
5. 相邻审查：重点检查未保存摘要被重新生成覆盖、取消编辑、空摘要/超长摘要、模型失败后旧摘要保留、重复作者信息、键盘与窄屏。确认可复现后修复。

## 验证

先添加合成失败用例，覆盖 SDK 路由与推理预算、视频控件污染和图文位置、三个入口、编辑保存与重试。再执行受影响包测试、类型/构建和实际 Electron 阅读回归，检查截图。真实文章链接仍待用户提供；不以合成数据替代真实模型效果验收。
