# 我的大脑：文章导入、阅读与标签管理需求

状态：用户已确认交互方向；本文件与同日执行计划用于下一模型接手。本文不代表功能已实现或测试通过。

## 1. 目标与范围

让用户从一个公开文章链接，完成有反馈的解析、结构化阅读、AI 摘要预览、修改标签、主动确认沉淀，并在以后按标签找回和移动文章。

本轮包含微信公众号与现有公开 HTTPS 导入链路、手工记录兼容、既有知识兼容。TAPD/iWiki 真账号验收另行由用户完成，不在本轮连接或修改其配置。不要更新官方 Harness 内核、重做整个产品、增加云端同步或自动复盘。

## 2. 已核查的现状

- `KnowledgeTab.tsx` 的 CaptureDialog 只有 busy 禁用，无阶段反馈；create 完成后立刻关窗。
- KnowledgeCard 直接渲染 item.content，操作按钮在长文底部。
- URL importer 将 snapshot 前 4,000 字作为 content；store 另保存完整文本快照，单份最多 1 MiB。不能把前 4,000 字标成全文或 AI 摘要。
- 桌面公众号 EXTRACT_SCRIPT 使用空白归一化，段落结构被压平；目前最大 200,000 字符与 store 字节限制不一致。
- 现有 refine 依赖 live session 模型，并直接 store.update 覆盖笔记。不能直接套用为“自动生成摘要”。
- category 和 tags 并存；新标签导航使用 tags，不擅自迁移或覆盖旧 category。
- 上一版五项隔离验收未充分覆盖长文布局、真实进度、AI 摘要和标签拖拽。其通过不能证明本轮要求已满足。

## 3. 确认的主流程

输入链接与可选标签 -> 开始解析 -> 读取文章 -> 整理正文 -> 按用户同意生成 AI 摘要 -> 预览 -> 暂存待确认或确认沉淀。

### 输入与进度

1. 用户可以选择历史标签，或输入新增标签；最多 8 个，每个 32 字符，去空白、去重，空值不保存。
2. 显示客户端已配置模型的 provider/model，不显示密钥。首次自动摘要默认不勾选；明确“解析后使用此模型生成摘要，将发送正文给该模型服务”。勾选后本次自动衔接，无需中间重复确认。只解析原文也可继续。
3. 点击后立即展示当前真实阶段、活动指示与已用时间。无可度量进度时不用百分比，不模拟完成，不承诺固定几秒。
4. 取消会取消本次工作，不在后台悄悄继续写入或调用模型。关窗必须明确取消还是暂存，不允许迟到响应重新打开或关闭另一个窗口。
5. 读取失败留在窗口，保留输入，显示安全错误和重试。遇到平台校验引导用户完成正常验证，不绕过验证。
6. 摘要失败保留已获取的原文和候选，允许只重试摘要或先保存原文；不能重抓全文或创建重复条目。

### 预览与编辑

- 独立详情阅读区，标题、作者（存在才显示）、来源、采集时间及截断提示可见。
- 原文 / AI 摘要 / 我的笔记分开展示；原文不可被模型输出覆盖；笔记与摘要允许用户编辑，标明人工修改。
- 原文保留标题层级、段落、列表、引用；无法识别层级就按段落安全降级，不让模型伪造原文结构。本轮不保证图片、公式和复杂表格的像素级还原。
- 默认不自动下载外部图片或跟踪资源；不执行文章 HTML、脚本、嵌入页面。来源链接只允许安全协议。
- 内容区可滚动，顶部关闭和底部操作栏始终可达；键盘也能操作。长文不扩张到覆盖整个列表。
- 点“确认沉淀”之前必须仍是 candidate。再次确认幂等，刷新/重启后状态和来源不丢失。
- 旧数据有 snapshot 时读取 snapshot；无 snapshot 时展示旧 content 并标注“历史笔记/片段”，不得声称完整原文或自动摘要。

### 列表与标签

- 列表卡片只显示短摘要或明确标记的正文摘录（最多约 180 字、视觉最多 4 行），标题与按钮可达；点击打开详情。
- 沉淀区有标签导航和数量。多标签文章在相应标签下都出现；“全部”按文章 ID 去重。
- 无 tags 时显示在“其他”；“其他”是空标签集合的虚拟分组，不持久化字符串。用户输入保留名称“其他”时给出明确提示，不创建同名普通标签。
- 历史标签来自待确认和已沉淀的非 dismissed 条目并集；删除最后一个引用后不保留空标签。本轮不建设独立标签目录或全局重命名管理。
- 从标签 A 拖到 B：移除 A，添加 B，保留其余标签；拖回 A 不变。从“全部”拖到 B：新增 B。从“其他”拖到 B：添加 B。
- 拖到“其他”意味着清空所有标签，必须先提示确认，取消后数据不变。
- 超过 8 个标签拒绝本次操作并解释，不默默丢弃。只允许已沉淀条目拖拽归类。
- 提供等价“移动到标签”菜单，支持键盘/触控，不把拖拽设为唯一入口。失败回滚，刷新后仍一致，不误覆盖并发编辑。

## 4. 数据、模型与安全

- 正文快照、AI 摘要、用户笔记有独立字段/存储；摘要记录 provider/model、生成时间、截断范围、人工编辑标记。没有摘要就不展示“AI 总结已生成”。
- 全文按字节限制，超限明确提示，不能无提示截取。模型输入继续有独立上限，超限则提示“仅基于部分原文生成”，本轮不隐含加入多轮长文总结。
- 正文详情按 ID 按需读取，列表不得传回所有全文；禁止前端传任意文件路径读取。
- 不读取/打印真实账号凭证；renderer 不获得 API key；不把 Cookie、Token、内部地址写入代码、日志、截图和报告。
- 文章和模型输出均视为不可信数据，不执行其中指令，不给摘要调用工具权限。错误显示固定错误码映射与建议，不回显正文、服务端原始响应或完整含参 URL。
- 继续使用现有官方 NPM SDK 与扩展机制，不编辑官方源码或 node_modules。禁止关掉 SSRF、TLS、浏览器 sandbox 等防护以让测试通过。
- RPC 取消与桌面 IPC 取消必须传到真实执行端。请求 ID 绑定调用方，不可取消其他窗口任务。模型调用前再次检查用户同意和所选模型仍可用。

## 5. 验收标准

1. 点击解析后一个渲染周期内看到 busy 阶段反馈；重复点击仅产生一次导入。
2. 20,000 字以上固定文章 fixture 能滚动到末尾；1280x800、900x650 与 125% 页面缩放时操作栏可见。
3. 解析完成不自动关窗；可预览正文、摘要、笔记，编辑标签后确认成功。
4. mock 模型生成可验证的摘要，原文 hash 不变；未同意时模型调用计数为零；无模型/断网/超时后原文仍可保存。
5. 应用新开无会话时也能选择已有配置模型生成摘要；不能要求用户先创建聊天作为隐形前置条件。
6. 旧记录正常读取，缺快照只降级单条记录；来源与 confirmedAt 不被摘要或移动标签修改。
7. 多标签拖动、全部视图添加、移动到其他确认、上限失败和刷新恢复符合上述规则。
8. 自动化验收使用合成文章、假模型、临时 DSH_HOME，不消耗真实模型额度，不连接真实业务系统。
9. 最后由用户在客户端测试公开公众号链接及已配置模型。其确认之前只称“隔离测试通过”，不称真实链路已通过。

## 6. 不在本轮范围

公众号付费/受限内容绕过、后台无人值守抓取、OCR、音视频转写、向量库替换、知识图谱、移动客户端、连接器重构、自动正式发布。上述事项不能成为这次交互修复的前置依赖。
