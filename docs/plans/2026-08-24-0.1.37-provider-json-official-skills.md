## Current implementation status (2026-08-25)

- **Completed:** provider JSON provenance/catalog onboarding, secure Skill package validation/install/rollback, guarded Tencent Meeting and WeCom official-source plans, and desktop preview → explicit confirmation → atomic install IPC/UI.
- **Still requires user-owned live acceptance:** paste the exact TAPD/Gongfeng JSON from signed-in provider pages; complete read-only TAPD/Gongfeng operations; install the provider-published Tencent Meeting package; run WeCom `auth init` and one read-only operation.
- **Intentionally not claimed as complete:** provider-side authorization success, token expiry/revocation recovery, and managed WeCom CLI authorization. Those remain the 0.1.38 lifecycle/live gates and must not be inferred from deterministic tests.

**Goal:** Verify and onboard TAPD and Tencent Gongfeng through provider-supplied MCP JSON, and install Tencent Meeting and WeCom through their official Skill/CLI paths.

**Architecture:** Reuse the canonical MCP JSON parser, encrypted connector secret store, and connector import transaction for TAPD/Gongfeng. Add a separate, security-reviewed official Skill installer that stages packages in the desktop main process, validates file structure and provenance, and installs into the existing DSH skill directory. Managed CLIs live under the desktop data directory rather than mutating the user's global npm installation.

**Tech Stack:** Electron main-process IPC, Node.js ESM, React, TypeScript, official provider JSON, ZIP/directory validation, SHA-256, Electron `safeStorage`, existing Skill discovery, pnpm workspace.

---

## Scope and hard boundaries

1. TAPD and Tencent Gongfeng configurations must come from the signed-in provider page or provider-owned documentation. Do not substitute community MCP packages or inferred endpoints.
2. Provider JSON is treated as user-supplied configuration, not executable trust. Stdio commands still require explicit local-execution consent.
3. Tencent Meeting follows the official Skill package and local Python proxy architecture. Its token is encrypted and injected as `TENCENT_MEETING_TOKEN` only at execution time.
4. WeCom follows `WecomTeam/wecom-cli`, the official CLI, and its official `skills/` directory. Do not repackage community skills as official.
5. The app must not run arbitrary shell snippets copied from provider pages. Installation recipes are parsed into allowlisted actions or replaced by a reviewed ZIP/directory import.
6. Managed CLI installation goes to `$DSH_HOME/desktop/tools/<provider>/<version>` and never requires `sudo` or a global npm install.
7. Every installed Skill records source URL, version/commit, SHA-256, install time, and verification tier without storing credentials.
8. If an official package URL or official JSON cannot be obtained, keep the item blocked/experimental. Do not mark the version item verified by using a third-party substitute.

## Definition of done

- The user's provider-supplied TAPD JSON imports with only missing token placeholders requested.
- The user's provider-supplied Gongfeng JSON imports without inventing endpoint or package values.
- Both connectors pass configuration, credential, runtime, and one read-only live tool check.
- Tencent Meeting Skill is installed from an official source, discovered by Harness, and completes one read-only meeting query with a test account.
- WeCom managed CLI and official Skills install, `auth show` works after guided authorization, and one read-only operation succeeds.
- Removing either Skill removes managed files and app-owned credentials but does not delete provider account data.
- macOS arm64, macOS x64, and Windows x64 deterministic tests pass.

**Step 1: Write failing package validation tests**

Reject:

- path traversal and absolute archive paths;
- symlinks escaping the staging root;
- packages without `SKILL.md`;
- manifests with invalid names or unsupported runtimes;
- executable files outside declared `scripts/`;
- archives above configured file-count/uncompressed-size limits;
- source redirects to a non-allowlisted host;
- checksum mismatches;
- package contents containing embedded token values.

Accept a minimal package with `SKILL.md`, `scripts/`, `references/`, and optional `config.json`.

**Step 2: Implement staged install**

Flow:

```text
download/select -> temporary staging -> validate -> hash -> preview -> explicit install -> atomic move to $DSH_HOME/skills
```

Do not execute scripts during validation. Preserve existing Skills unless the user explicitly approves replacement.

**Step 3: Add removal and rollback**

Keep one previous app-managed version until the new package passes discovery. User-created Skills are never overwritten or removed by this manager.
