## Release rules

1. Never commit provider JSON, tokens, tenant IDs, account identifiers, private URLs, or raw provider responses.
2. A deterministic parser or simulator pass does not make a connector “verified”.
3. TAPD acceptance starts with a read-only query. Create, edit, delete, deployment, and repository-write operations remain out of scope.
4. Providers without dated redacted evidence stay `experimental`; they do not block the desktop release.
5. Preserve all current working-tree changes. Do not reset, stash, or overwrite unrelated files.

Expected: the connector card appears as connected or returns a specific credential/network diagnosis; no generic JSON parse error and no infinite boot screen.

**Step 2: Run one read-only operation**

Use a disposable or least-privilege token to list accessible TAPD projects/workspaces or read one non-sensitive test item.

Expected: a successful tool response reaches the conversation and the second session reuses the encrypted credential without requesting it again.

**Step 3: Verify lifecycle recovery**

1. Rotate or revoke the disposable token at TAPD.
2. Refresh/check the connector.
3. Confirm the UI enters `reauthorization-required` rather than retrying forever.
4. Reconnect with the replacement token and repeat the read-only query.
5. Disconnect and remove the connector; confirm public inventory contains no credential-shaped values.

**Step 4: Record redacted evidence**

Record only provider, date, transport, operation category, pass/fail, lifecycle result, desktop version, and platform. Validate the local evidence directory before using it to change a store tier.
