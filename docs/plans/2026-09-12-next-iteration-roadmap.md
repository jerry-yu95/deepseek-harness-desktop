# JIWEI 下一阶段迭代路线建议

日期：2026-09-12。状态：建议稿，供产品范围讨论；本次仅规划，不代表功能实现、真实账号操作、提交或发布授权。

## 目标与依据

继续面向低门槛 Agent 使用者和产品经理，让一次任务产生的知识在后续任务里可找到、可引用、可恢复。

当前基点为 f4fd631 加未提交工作区。三个受影响包共 427 项测试通过；两包类型检查和构建、源码 Electron 回归已通过。当前 arm64 DMG 包含修复，沿用 0.1.44，镜像内知识 7/7 和通用验收 5/5 通过。它是本地 ad-hoc 签名测试包；真实模型、TAPD/iWiki/微信网络、Hosted CI、其他平台及更新回滚仍有待验项。详见 [当前验收报告](../qa/0.1.45-release-report.md)。

本次源码核查发现：

- `packages/dsh-extension-center/src/client/panel/KnowledgeTab.tsx` 的搜索拼接标题、content、标签和分类；该逻辑未检索独立原文快照及 AI 摘要。已有搜索应扩展和验证，不需重做列表。
- `packages/dsh-knowledge/src/index.ts` 当前注册 `knowledge_propose` 工具，支持候选沉淀；未在该插件注册会话知识检索/读取工具。UI 可读知识不等于 Agent 已能检索复用。
- `apps/dsh-desktop/src/update-manager.mjs` 的 profile 备份复制四个配置文件，不包含知识条目、原文和图片。不能用配置备份的存在证明知识库可恢复。

这些是定向核查结论，不是对所有插件与官方运行时能力的完整审计。实现前还需核对官方 SDK 的会话扩展接口。

## 路线取舍

| 路线 | 优势 | 代价 | 建议 |
| --- | --- | --- | --- |
| 知识检索、会话引用、后续复用 | 直接验证 JIWEI 的持续积累价值，复用现有存储/UI | 需要解决召回、引用时点、上下文预算 | 下一轮产品主线 |
| 扩展更多连接器和授权方式 | 扩大可执行工作范围 | 企业网络和服务方协议增加验收成本 | 先把一个常用服务验收到实际只读业务请求，再决定扩展 |
| 增加任务模板、新手引导和视觉优化 | 降低第一次使用成本，便于演示 | 不能单独证明知识复用或长期可靠性 | 与真实试用反馈结合，排在核心闭环之后 |

## 迭代顺序与验收目标

以下按验收结果分轮，不承诺固定工期或版本号。外部账号及 CI 等待不计作开发完成；发现阻断问题时，先修复再进入后续轮次。

### 第 1 轮：验证当前测试包的真实工作闭环

主要产出：当前测试包的真实使用记录、阻断问题清单、可复现的源码基线。

1. 在用户安排下完成安装/升级测试；先明确数据位置和恢复办法。包内启动通过不替代覆盖旧安装、保留知识及回滚验收。
2. 用一个常用真实模型、一篇带图文章和一个常用连接器，走通资料读取、摘要、人工编辑、沉淀、重启后读取。连接器至少验证一次实际只读业务请求，而不止工具发现。
3. 增加取消、模型错误、网络中断、授权过期等真实失败路径的脱敏记录；仅在有证据时修复。
4. 将混合工作区按审阅地图整理为可追溯基线；提交、推送和 Hosted CI 执行依会话授权安排。随后完成 Node 24 干净安装、全仓测试/类型检查/构建及聚合检查。若保持三平台发布目标，应补齐另两平台打包验收。

验收：核心流程没有阻断性错误；授权/网络失败有明确反馈，已保存知识在重启后仍可读；每项发布门禁都有当前证据或明确待验状态。TAPD/iWiki 等服务未实际验证前不扩大能力宣传。

### 第 2 轮：知识找得到、能带入当前任务

建议这是下一轮开发的最小完整范围。

1. 扩展当前搜索：覆盖原文、摘要、笔记和标签，显示命中片段及来源。先建立中文关键词、同义表达、长文与无结果的合成评估集；检索方案以实际效果和响应时间选择。
2. 在知识条目或会话中提供显式“用于当前任务”流程。用户能预览选中的内容、移除条目、看到数量和来源；未发送前允许撤回选择。
3. 为会话引用定义稳定的条目 ID、版本或引用时点、来源信息及长度上限。先传相关片段，必要时通过受限读取补充，避免把全部长文持续注入上下文。
4. 只自动检索已沉淀条目；待确认、已忽略条目不作为已确认事实。被删除或不可用的来源提供可理解反馈；保留原文与知识版本的设计需先确定。

验收：准备包含“相关知识、干扰知识、无结果、内容更新”的测试集，预先定义期望命中项；用户在新任务中能找到并引用目标知识；对话展示实际使用的来源；取消选择后不再带入；超长内容不挤占整个上下文。项目隔离若尚未实现，不宣称已支持。

实施核查入口：`packages/dsh-knowledge/src/core/store.ts`、`src/index.ts`、`src/wire.ts`、`src/client/api.ts`，扩展中心知识 UI，以及 `packages/dsh-text-context/src/client/` 的现有引用接入。仅复用官方 SDK 扩展接口，不修改官方运行时。

本轮先做用户主动引用。Agent 主动检索和自动推荐在上述效果可评估之后加入；向量数据库、云同步与知识图谱留作后续方案选择。

### 第 3 轮：知识可导出、可恢复

该轮可提前到第 2 轮之前，条件是准备大量导入正式资料、做存储迁移或覆盖安装测试。

1. 明确备份范围：条目、分类标签、原文、摘要、图片及必要来源元数据；将账号凭证排除在知识导出之外。
2. 提供用户可读的导出形式，以及带版本和校验信息的完整恢复格式。恢复前展示新增、重复、冲突和缺失资源，默认保留现有数据。
3. 增加损坏文件、重复导入、部分资源缺失与中途取消的恢复验证。大批量导入前先用合成知识做完整恢复演练。

验收：导出后能在全新隔离配置中恢复同样的条目数、状态、标签、正文和图片；损坏备份不会破坏已有知识；配置备份和知识备份在 UI/文档中清楚区分。

### 第 4 轮：产品经理常用任务与首次使用体验

先从试用中选择一个高频任务，例如“根据需求与资料生成评审问题”或“把复盘转为可复用检查清单”。每个任务定义输入、输出和知识沉淀时机，验证后再扩展第二个模板。

引导围绕配置模型、完成首个任务、确认第一条知识展开。失败提示直接提供相关操作：修改模型配置、重新授权、取消或重试。基于实际失败补齐体验，避免重复实现现有诊断状态。

验收：邀请少量目标用户，在无人代操作的情况下完成首个任务和一次沉淀；记录完成时间、卡点及是否在后续任务中复用。样本不足时保留原始观察，不把小样本转成稳定转化率结论。

## 每轮观察的结果

记录操作成功与否、失败类别、寻找目标知识所需时间、是否实际引用到任务中，以及恢复是否完整。优先使用合成测试和经用户同意的本地试用记录；不新增默认上传正文或用户行为的遥测。

当前推荐：先完成第 1 轮真实验收，再把“原文/摘要搜索 + 显式会话引用”作为下一轮主要功能。知识恢复在正式数据扩量前落实，连接器扩展和自动推荐由实际使用证据决定。
