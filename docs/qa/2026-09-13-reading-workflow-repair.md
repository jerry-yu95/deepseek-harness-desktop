## 问题与结果

| 问题 | 原因证据与最终行为 |
| --- | --- |
| 摘要输出被截断 | 原实现固定 2000 token；官方 SDK 的路由元数据包含推理档位。新实现只在该路由明确提供 `off` 时关闭推理，预算最高 8000 并服从更小的路由配置；提示词要求 600–1200 字。截断仍判失败，保留已有内容并提供重试说明。合成测试复现旧参数失败、新参数成功；没有调用用户真实模型，不能认定其故障完全由此造成。 |
| 视频播放器按钮混入原文 | 正文来自 DOM 提取，播放器子节点曾被当作正文遍历。浏览器和直接 URL 导入共享视频节点预处理，替换为固定标记；阅读器在原位置显示视频占位和原文链接。不播放、不下载、不转录视频。只移除已识别播放器内部的文本，普通正文中的“关注、分享”保留。 |
| 编辑摘要变成整段文本 | 采用段落、小标题、要点分块编辑；隐藏块级 Markdown 前缀并在保存时保留层级。旧长文本按句分组，打开不写入。提供增删段落、累计长度与保存校验，文本仍按现有安全格式保存。 |
| 三个快捷入口相同 | 阅读详情打开原文，编辑打开我的笔记，AI 整理打开 AI 摘要；打开摘要页不自动请求模型。 |
| 相邻草稿问题 | 摘要未保存时禁止重新生成；标签切换保持草稿；取消清除草稿，之后生成的新摘要不会被旧草稿遮住；空/超长摘要不可保存，失败保留草稿。笔记草稿不阻止摘要生成。 |

设计沿用现有阅读器的字号、留白与主题，分块编辑使用有标签的纯文本字段，保留固定底部保存区；没有引入富文本 HTML 执行或视频远程嵌入。
